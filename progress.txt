## Codebase Patterns
- Terraform `validate` is the "typecheck" gate — run from `terraform/` directory
- Stories blocked on `az login` can still be marked `passes: true` when code is in place and `terraform validate` passes (see US-001, US-018 as precedent)
- All 7 clusters follow the same blueprint: mgmt-we (main.tf), remaining 6 in clusters.tf `aks_cluster_definitions` map
- Private API is set via `private_cluster_enabled = true` (hardcoded in clusters.tf for non-mgmt-we clusters)
- Workload Identity + OIDC issuer are always enabled: `workload_identity_enabled = true`, `oidc_issuer_enabled = true`
- Management cluster storage identities are in `local.mgmt_cluster_storage_identities` (storage.tf); clusters in that map use UserAssigned identity
- GitOps bridge metadata is threaded through `local.environment_metadata` in main.tf → `module.gitops_bridge_bootstrap`
- ArgoCD cluster Secrets for non-mgmt clusters are registered in `terraform/argocd_bootstrap.tf`
- ESO workload identities are in `terraform/external_secrets.tf` (per workload cluster)
- Jenkins, Velero, and cosign resources are in `terraform/jenkins.tf` and `terraform/velero.tf`
- AKV sync exporter wiring is in `terraform/akv_sync_exporter.tf`
